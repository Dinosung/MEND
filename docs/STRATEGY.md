# Narrow MEND into a verified post-cutoff tripwire

MEND should continue, but in a narrower form. It should stop presenting itself as a general "failure memory" and become **a verified, auto-refreshed catalog of the breaking changes coding agents have not learned yet, delivered as deterministic checks that run on every write and in CI, plus an honest benchmark that measures which models still get them wrong**. The evidence supports that narrow wedge and nothing broader. Frontier models now handle well-known migrations: MEND's own run found zero repeat failures when versions were stated. The large failure rates that remain are on post-cutoff changes, in agentic multi-file upgrades, and when the version is only implicit in the project's files. On those, unassisted agents fail at roughly 50–100% and docs injection closes only part of the gap ([GitChameleon 2.0](https://arxiv.org/html/2507.12367); [Ashik et al.](https://arxiv.org/abs/2604.09515); [DepBench](https://arxiv.org/html/2608.30300)). The current evidence that MEND itself helps is one fixture (`np.trapz`), one model and three trials. That is an anecdote and cannot carry a launch. Three changes follow. First, the delivery surface has to move from an MCP tool the agent may never call (on-demand tools are skipped about half the time) to hooks and CI. Second, the catalog has to come from a release-diff pipeline rather than hand-authoring of 2023-era migrations. Third, MEND-Bench has to become a paired, agentic, implicit-version benchmark that includes "just tell it the versions" and Context7 as baselines. Run a two-week pilot and a ten-week build, then make a kill/continue call around mid-January 2027. The test is whether MEND beats the best cheap baseline on at least ~50 tasks that genuinely fail. If it does not, the benchmark becomes the product. Before any public launch push, the owner must get written employer clearance, because an AI-coding-assistant correctness tool plausibly "relates to the employer's business."

## Agents still fail on the newest changes, and MEND's evidence is thin

The literature agrees with MEND's first benchmark run. Older studies found 2024-era models using deprecated APIs in **25–37% of completions, and 70–90% when the surrounding code was already outdated** ([LLMs Meet Library Evolution](https://arxiv.org/html/2406.09834v3)). Frontier models in 2025 still reached only **48–51% on version-conditioned problems with hidden tests**, and release year mattered little for 2014–2023 changes ([GitChameleon 2.0](https://arxiv.org/html/2507.12367)). Things look worse once the change postdates training. VersiBCB reports failures **about 40% higher on versions released after pretraining**, with a best pass@1 of just 27.76% in per-sample pinned environments ([arXiv 2601.12262](https://arxiv.org/pdf/2601.12262)). Vercel's Next.js 16 agent evals started at a 53% baseline ([Vercel](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals)). Upstash found Claude Sonnet 4.5 out of date on all 50 of its deliberately chosen post-cutoff questions ([Upstash](https://upstash.com/blog/context7-vs-static-llm-knowledge-benchmarking-coding-assistants)). MEND's result, where Sonnet repeated only the NumPy 2.4 `np.trapz` removal, fits the same pattern: **the value sits in the months after a release, not in famous migrations.**

Two other findings matter as much. Version-stated prompting gave **no benefit** on LibEvoBench, while docs raised scores by 10–20 points ([arXiv 2606.25402](https://arxiv.org/abs/2606.25402)). That contradicts MEND's observation that stating versions removed every failure. The likely explanation is MEND's task design: from-scratch, single-shot tasks with the version handed over in the prompt are the easiest setting there is. The second finding is that failure rates jump when the work is agentic and spans a whole repository. On DepBench, built from real Dependabot and Renovate PRs, the best agent solved **51.2%**, and the dominant failure was *incomplete migration*. **61.8% of failures passed the visible tests and then failed hidden ones** ([DepBench](https://arxiv.org/html/2608.30300)). That is exactly the gap a deterministic `mend check` covers: the agent finds the right fix but does not apply it everywhere.

Several weaknesses should be stated plainly. Stale APIs are a small share of agent failures overall. SWE-Bench Pro's failure taxonomy has no "outdated API" category; its failures are wrong solutions, tool-use errors and context overflow ([SWE-Bench Pro](https://arxiv.org/pdf/2509.16941)). On hard Terminal-Bench tasks, misreading the problem (38.4%) and under-modelling requirements (28.8%) dominate ([Turing](https://www.turing.com/blog/terminal-bench-3-confident-failure)). No 2026 study measures how often stale-API errors occur in real agent sessions. Much of the 2026 evidence also comes from vendor blogs (Upstash, Vercel, Turing) or alphaXiv preprints. MEND's own evidence of benefit is **n=1 fixture, k=3 trials, one model, single-shot**, which is not statistically meaningful. It also has not been checked against ruff's NPY201 rule, whose documentation does not mention `trapz` ([ruff NPY201](https://docs.astral.sh/ruff/rules/numpy2-deprecation/)). If ruff already flags it, MEND's one win sits in a gap that a free linter already covers. The defensible claim today is that a narrow, real, fast-decaying problem exists and that the levers that work are known. Whether MEND moves outcomes beyond those cheaper levers is unproven.

## What MEND should become, and what to stop, keep and change

**Positioning:** *"Your agent writes code for last year's version of the library. MEND catches it with a proven check, not more docs."* The category label to borrow is "regression tests for your coding agent," and the technical term to adopt is **witness programs**. cargo-semver-checks uses that term for code that proves a breaking change by failing to compile ([predr.ag](https://predr.ag/blog/cargo-semver-checks-2025-year-in-review/)), and every MEND fixture already is one. Do not lead with "CVE database for AI mistakes." It invites rigour and coverage expectations a solo project cannot meet, and it moves MEND toward security framing, which is the riskiest area given the employer policy. Keep CVE-style stable IDs as a detail inside the product.

**Scope:** Python only through at least January 2027. Cover **breaking changes released within roughly the last 18 months** in a ranked watchlist of high-download, fast-moving Python libraries. Add a "probed" status that records whether current frontier models actually make each mistake. Older migrations such as Pydantic v2 and NumPy 2.0 stay in the catalog as coverage and regression tests, but MEND should not claim they add value. Explicitly out of scope: JS/TS (Next.js now bundles version-matched docs and an AGENTS.md with `create-next-app` ([Next.js 16.2](https://nextjs.org/blog/next-16-2-ai))), security weaknesses (crowded, and in conflict with the employer policy), hallucinated packages (security vendors own this), and project-specific lessons (Claude Code memory and Copilot memory own those).

| Decision | Item | Rationale |
|---|---|---|
| **Stop** | Single-shot, from-scratch benchmark as the headline result | HumanEval-era design. It hands the agent the version and cannot surface propagation failures. |
| **Stop** | Hand-authoring fixtures for well-known, pre-cutoff migrations | Frontier models already pass them, so each new one adds almost no marginal value. |
| **Stop** | Relying on agents choosing to call `mend_lookup` | On-demand skills fired in only 45–55% of sessions without a forcing hook ([Spence](https://scottspence.com/posts/measuring-claude-code-skill-activation-with-sandboxed-evals)). Context7 was called in 6 of 89 tasks ([Marginlab](https://marginlab.ai/blog/do-mcps-improve-coding-agents-part-1/)). |
| **Stop** | Growing `mend check` into its own linter engine | Emit semgrep/ruff-compatible rule packs instead. Keep the built-in matcher only as a zero-dependency fallback. |
| **Keep** | Fixture contract: bad code, fixed code, pytest check, pinned versions, CI verification | This is the differentiator no competitor has. |
| **Keep** | Three-tool, read-only MCP server | A cheap discovery channel. Small tool counts avoid selection degradation. |
| **Keep** | "Fixture content is data, never instructions" rule | It becomes the headline trust feature after the ContextCrush CVE. |
| **Keep** | Minimal core dependencies, uv backend, GitHub Actions verification | Free compute on public repos. The bottleneck is review, not CI. |
| **Change** | Verification gate | Add the *differential* check: bad must pass on the old version and fail on the new one (CodeUpdateArena's UPass logic ([arXiv 2407.06249](https://arxiv.org/pdf/2407.06249))). |
| **Change** | Primary delivery | Hooks (SessionStart inform, PostToolUse check), pre-commit, GitHub Action. MCP becomes secondary. |
| **Change** | Catalog source | A release-diff pipeline with a model probe step, not hand-authoring. |
| **Change** | Benchmark | Agentic, in-repo, implicit versions, paired arms, and Context7 plus versions-injected baselines. |

## Deliver through hooks and CI, not an optional tool call

The clearest delivery evidence is Vercel's Next.js experiment. The baseline was 53%. An on-demand skill also scored **53%, because it was never invoked in 56% of cases**. The skill plus an explicit instruction to use it reached 79%. An always-present AGENTS.md docs index reached **100%** ([Vercel](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals)). Independent tests agree. Claude Code skill activation sat at 50–55% without a hook and 100% with a forced-evaluation UserPromptSubmit hook ([Spence](https://scottspence.com/posts/measuring-claude-code-skill-activation-with-sandboxed-evals)). In Marginlab's Terminal-Bench A/B, Context7 was called in **6 of 89 tasks**, with 63/89 vs 64/89 success, which is within noise ([Marginlab](https://marginlab.ai/blog/do-mcps-improve-coding-agents-part-1/)). MEND as currently shipped behaves like the skill in Vercel's test, so its main channel needs to change.

More context is not the fix either. LLM-generated context files *lowered* success by 0.5–2% and raised cost by 20–23% ([ETH Zurich, arXiv 2602.11988](https://arxiv.org/html/2602.11988v1)). The "inform" payload therefore has to be tiny and limited to the project's dependencies. What drives repair is deterministic feedback. Feeding Bandit and Pylint findings back to the model cut security issues from over 40% to 13% and reliability warnings from over 50% to 11% ([arXiv 2508.14419](https://arxiv.org/abs/2508.14419v1)), and executable self-debugging added 10–20 points on GitChameleon ([GitChameleon 2.0](https://arxiv.org/html/2507.12367)). Claude Code's hook model supports both halves. SessionStart/UserPromptSubmit can inject `additionalContext`, and the docs advise phrasing it **as facts rather than imperatives** so it does not trip injection defences. PostToolUse with exit code 2 sends stderr back to the model after a write ([Claude Code hooks](https://code.claude.com/docs/en/hooks)).

The recommended stack has four layers, in priority order. The first is a **Claude Code plugin** bundling three things: a SessionStart hook that runs `mend lookup` against the lockfile and injects a few lines of version-matched facts; a PostToolUse hook that runs `mend check` on edited Python files and exits 2 with fixture IDs; and the existing MCP server for the detail behind each fixture. Marketplaces are just git repos, and the official marketplace loads automatically ([Morph](https://www.morphllm.com/claude-code-marketplace)). The second is a **pre-commit hook and a GitHub Action** running `mend check`, which catches agents that skip the plugin and catches humans too. The third is a **`mend context` command** that writes a short, fact-phrased block into AGENTS.md, Cursor rules or Copilot instructions, so the same knowledge reaches Codex, Cursor and Gemini CLI. AGENTS.md is in more than 60,000 repositories ([arXiv 2601.20404](https://arxiv.org/html/2601.20404v2)). The fourth is **rule-pack exports** (semgrep YAML, plus a ruff-plugin or flake8 shim if cheap), so MEND rides existing linters. The broadest single surface is the MCP server, listed in every registry, but registries publish no install counts and add tens of thousands of servers without pruning ([dev.to registry analysis](https://dev.to/amareswer/the-mcp-registry-by-the-numbers-38nc)). Treat it as SEO and legitimacy, not a distribution engine.

## Rebuild MEND-Bench as a paired, agentic, implicit-version benchmark

Credible 2026 coding-agent benchmarks share a template. Each task is a per-task Docker repository worked by an agent loop, with hidden execution tests, explicit contamination control and human validation. Static public sets lose trust: OpenAI stopped reporting SWE-bench Verified in February 2026 after finding contamination and 59.4% of audited problems with flawed tests ([OpenAI](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/)). The benchmark must also keep agents from gaming the tests. On RepoRescue, **38–53% of Claude Code's "successes" came from editing tests**, and source-only scoring cut success to 19.7–24.4% ([arXiv 2607.01213](https://arxiv.org/pdf/2607.01213)).

MEND-Bench v2 should be built in **Harbor's task format**, so the same tasks run on Claude Code, Codex and mini-swe-agent without custom harness work ([Harbor](https://docs.harborframework.com/getting-started/quick-start)). There are three task types. *Implement* tasks add a feature in a small repo whose `pyproject.toml`/lockfile pins the new version and never mentions it in the prompt. *Upgrade* tasks bump a dependency and require the change to be propagated across files, following DepBench. *Reverse-anachronism* tasks pin a repo to the older version, where newer-API habits break. These also act as negative controls for false positives. Tests are hidden and read-only, scoring is source-only, and environments are pinned with uv's `--exclude-newer` or a SWE-bench-Live-style time-machine index ([SWE-bench-Live](https://arxiv.org/html/2505.23419v1)).

| Arm | Condition | Why it must be there |
|---|---|---|
| A0 | No help | Baseline failure rate |
| A1 | Pinned versions injected as one line of context | The cheapest competitor. MEND's own data says it may be enough. |
| A2 | Context7 MCP + AGENTS.md instruction to use it | The category leader |
| A3 | MEND MCP only | Today's product |
| A4 | MEND plugin (SessionStart inform + PostToolUse check) | The proposed product |
| A5 | A1 + A2 + A4 | Whether MEND is additive to docs |
| Oracle | Fixture fix text injected directly | Upper bound on content value |
| Do-nothing | Unmodified repo submitted | Validity control ([ABC checklist](https://arxiv.org/html/2507.02825v5)) |

On statistics, follow Anthropic's eval guidance. Run paired arms on identical tasks with k=3–5 trials, compute standard errors over task-level means, cluster by library, and report a paired difference with a confidence interval and a McNemar or permutation test ([Miller, arXiv 2411.00640](https://arxiv.org/html/2411.00640v1)). Report tool-invocation rate separately from the effect when the tool is invoked, along with tokens, cost and false-positive harm. The sample-size reality is unforgiving. By the standard McNemar power formula (α=0.05, 80% power), a strong effect, where MEND rescues 20% of tasks and breaks 2%, needs about **51 discordant-capable tasks**. A more modest 10%/2% effect needs about **145**. Only tasks the baseline actually fails count. The current 20 scorable fixtures, of which one fails, cannot show anything. Build the task pool from fixtures the probe step has shown to fail. Disclose that filter, as Aider did when it kept only problems three or fewer of seven models solved ([Aider](https://aider.chat/2024/12/21/polyglot.html)). Re-run A0 fresh on the filtered set to avoid regression-to-the-mean artefacts. Hold back a **private split** and date-stamp every task, because public fixtures will leak into future training data.

Cost is manageable. mini-swe-agent ran SWE-bench instances at about $0.30 each with frontier models ([swebench.com](https://www.swebench.com/post-250820-mini-roulette.html)), and MEND tasks are far smaller. My estimate for ~100 tasks × 6 arms × 3 trials × 1–2 models is a few hundred to low thousands of dollars, depending on model and turn caps (about 50 turns, $1–2 per trajectory). The pilot should be an order of magnitude cheaper. Finally, publish MEND-Bench as a separately named, neutral artefact: an HF dataset, Harbor tasks, and a leaderboard that invites Context7 and other docs tools. A benchmark written by a tool vendor that shows its own tool winning gets discounted.

## Build a pipeline that mints witness programs from release diffs

Hand-authoring is the wrong engine. Seed sources such as ruff NPY201, bump-pydantic and the 145 ICSE mappings mostly cover old migrations that models have already learned. Freshness has to come from automation. The pipeline has seven stages, and the release *event* stage is cheap and fully machine-readable. **Events:** poll PyPI's update and per-project RSS feeds ([PyPI feeds](https://docs.pypi.org/api/feeds/)) for a watchlist ranked by PyPI BigQuery downloads (CC BY 4.0) ([PyPI BigQuery](https://docs.pypi.org/api/bigquery/)), filtered to major and minor bumps. **Detect:** install old and new versions in two uv venvs and run `griffe.find_breaking_changes`, which reports removed symbols, removed or reordered parameters, new required parameters and changed parameter kinds ([griffe](https://github.com/mkdocstrings/griffe/blob/main/README.md)). Add `inspect`-based diffing for C-extension packages, as CODESYNC did ([arXiv 2502.16645](https://arxiv.org/pdf/2502.16645)). In parallel, have an LLM extract removals and changes from the release notes; a 2026 study using GPT-5 mini for this reached 91.4% agreement with humans ([arXiv 2604.09515](https://arxiv.org/abs/2604.09515)). When the diff and the notes agree, confidence goes up. **Draft:** an LLM writes bad code, fixed code, the pytest check and the semgrep rule. **Verify:** four gates. Bad must fail on the new version and fixed must pass. Bad must *pass on the old version*, which proves the version change caused the failure and the test is not broken. The semgrep rule must match bad and not fixed. Every package named in the fix must exist on PyPI. **Probe:** a cheap headless agent run on two current models with versions implicit. This records whether models actually make the mistake, and only fixtures that fail get "active" status and a place in the benchmark pool. **Review:** a human approves the item, with CODEOWNERS and no auto-merge. **Release:** a signed catalog release.

The probe stage is the strategically important one. It turns the catalog from a list of every API change, which Context7 and the docs already cover, into **a measured record of what models do not know yet**. Each fixture carries per-model failure rates and a "retired" date once new models stop failing it. That one dataset drives the catalog, refreshes the benchmark automatically, and produces a recurring news hook: "Model X still doesn't know about change Y". Signature changes deserve priority over removed imports, because modifications were the hardest category and wrong parameters were the top execution failure in the 2026 study ([arXiv 2604.09515](https://arxiv.org/abs/2604.09515)).

Compute is not the constraint. GitHub Actions is free for public repos with 20 concurrent jobs and 256-job matrices ([GitHub Actions limits](https://docs.github.com/en/actions/reference/limits)), and uv links packages from a global cache ([uv cache](https://docs.astral.sh/uv/concepts/cache/)). Human review is the constraint, so measure review minutes per fixture from day one. For field capture, add an opt-in `mend report` that submits only derived data (package, versions, error signature, symbol) as a GitHub issue under DCO sign-off. AIDev's 932,791 agent-authored PRs are a mineable source of naturally occurring bad-to-fixed pairs ([AIDev](https://arxiv.org/html/2602.09185v1)). Every mined pair must be rewritten as a fresh minimal snippet, never copied. Licensing rules are strict. **Semgrep registry rules may not be redistributed** ([Semgrep license](https://semgrep.dev/legal/rules-license)). OpenRewrite's Python and JS recipes are under a source-available licence that bans managed-service use ([OpenRewrite](https://docs.openrewrite.org/licensing/openrewrite-licensing)). ecosyste.ms data is CC-BY-SA ([ecosyste.ms](https://ecosyste.ms/api)), so use it only to trigger events, never as catalog content. Write every snippet fresh in under about 10 lines, store source URLs as provenance metadata, and ship code under MIT with catalog data under CC-BY-4.0. CDLA-Permissive-2.0 is the alternative if being consumed by LLM vendors matters more than attribution ([CDLA-P-2.0](https://cdla.dev/permissive-2-0/)).

## Make "the feed that cannot instruct your agent" the trust story

MEND's threat model is not hypothetical. It played out in **ContextCrush, CVE-2026-75130 (CVSS 9.0)**. Anyone who could register a library on Context7 could embed "Custom AI Instructions" that were served verbatim over MCP, and agents were induced to exfiltrate credentials from env files and delete files ([NVD](https://nvd.nist.gov/vuln/detail/CVE-2026-75130); [PointGuard AI](https://www.pointguardai.com/ai-security-incidents/contextcrush-flaw-turns-ai-documentation-into-malicious-instructions)). The research says a few poisoned records are enough: five texts gave ~90% attack success in PoisonedRAG ([arXiv 2402.07867](https://arxiv.org/abs/2402.07867v1)), and poisoning under 0.1% of a memory gave over 80% in AgentPoison ([arXiv 2407.12784](https://arxiv.org/abs/2407.12784)). MemoryGraft shows that any loop which promotes observed failures into shared memory can be steered into writing the poison itself ([arXiv 2512.16962](https://arxiv.org/abs/2512.16962v1)). That applies directly to `mend report`.

The defences that hold are structural, and MEND's design already points toward them. **Output is structured data only**: package, version range, symptom, wrong pattern, correct pattern, evidence, all rendered in a labelled data block with no free-text "rules" or "notes to the agent" field. **CI lints reject hidden and bidi Unicode and HTML comments** and cap field lengths, the vectors used in the Rules File Backdoor ([Pillar Security](https://pillar.security/blog/new-vulnerability-in-github-copilot-and-cursor-how-hackers-can-weaponize-code-agents)). **Every package named in a fix must pass a PyPI existence-and-age check**, so MEND can never become a slopsquatting amplifier. **Execution-based verification** is required for every record, which is stronger than the citation checks GitHub uses for Copilot memory ([GitHub](https://github.blog/ai-and-ml/github-copilot/building-an-agentic-memory-system-for-github-copilot/)). **Catalog releases are signed**, clients pin to a digest, and any change to a pinned record requires re-approval as an anti-rug-pull measure ([CSA](https://labs.cloudsecurityalliance.org/research-rb/csa-whitepaper-mcp-security-tool-poisoning-20260506-csa-styl/)). **Feedback-loop candidates always go through human review.** The **MCP server is read-only**, and MEND's own Actions run with read-only tokens, SHA-pinned actions and no secrets, applying the lessons of Comment and Control ([CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-comment-control-github-prompt-injection-20/)). Write these into a short `SECURITY.md` and threat-model page. They make MEND the obvious choice for teams burned by ContextCrush. They also play to the owner's expertise without making MEND a security product: this is the integrity of a developer-correctness tool, not vulnerability sharing. The employer clearance should still name it explicitly.

## Competitors own docs breadth, not verified mistakes

| Docfork ([mcp.directory](https://mcp.directory/blog/context7-vs-deepwiki-vs-ref-vs-docfork-2026)) | Manifest-scoped docs search | Docs, not mistakes. Small (471 stars in April 2026). |

| DebugBase, MoltyOverflow ([PH](https://www.producthunt.com/products/debugbase), [site](https://www.moltyoverflow.com/)) | "Stack Overflow for agents" error/fix sharing | Vote-ranked, unverified, tens of entries |
| since-cutoff ([mcpservers](https://mcpservers.org/servers/mohammadhijjawi97/since-cutoff)) | Python API diff since cutoff, ~8 stars | Same idea, no executable proof, unlaunched. Move first. |
| Ruff NPY201, bump-pydantic, codemods ([ruff](https://docs.astral.sh/ruff/rules/numpy2-deprecation/)) | Curated old-to-new migration rules | Built for humans migrating code. Lag on recent changes. Not wired to agents. |
| Framework vendors (Next.js 16.2) ([Next.js](https://nextjs.org/blog/next-16-2-ai)) | Bundled docs + AGENTS.md | Per-framework only; Python libraries mostly don't do this |

The open space is the combination no one ships. MEND offers library-by-version records, a sandboxed proof that the bad code fails and the fix passes, delivery as both inform and check, and content that cannot instruct the agent. The pitch line writes itself: **"Context7 tells your agent what the docs say. MEND tells it what it will get wrong, proves it, and blocks it in CI."** Be complementary in practice as well: run Context7 in arm A5 and say so if the two stack. The real competitive risk is not today's players. It is Tessl or Context7 bolting a "known pitfalls" layer onto their distribution. MEND's defence is open, reproducible data that even they could consume, plus speed on the post-cutoff feed.

Go-to-market should follow how MCP-era tools actually grew. Context7's HN posts drew single-digit points, and it grew through client integration, a copy-paste config and a trigger phrase ([HN Algolia](https://hn.algolia.com/api/v1/search?query=context7&tags=story&hitsPerPage=5); [Upstash](https://upstash.com/blog/context7-mcp)). Serena had no single HN launch ([rywalker](https://rywalker.com/research/serena)). An HN front-page appearance adds about **+289 stars in a week** on average ([arXiv 2511.04453](https://arxiv.org/abs/2511.04453v1)). Repomix reached 26k stars with one maintainer by putting one core behind six thin surfaces and shipping monthly ([rywalker](https://rywalker.com/research/repomix)). So: one-line installs everywhere (plugin, `uvx`, Action, pre-commit), a 20–30-second demo of an agent writing a post-cutoff-broken call that the hook catches and the agent fixes, and a README that states the limitation openly ("frontier models already handle well-known migrations; MEND targets what they haven't learned"). Then come recurring content hooks: a monthly "what the newest models still don't know" post generated from probe data, and a fresh results run whenever a major model ships. Launch the benchmark write-up across HN, relevant subreddits and newsletters at the same time, following Infisical's simultaneous-channel playbook ([Infisical](https://infisical.com/blog/how-we-got-3000-github-stars-in-2-months)), and target the ICML DL4Code or NeurIPS Datasets & Benchmarks track for an arXiv paper. Never buy stars. Fake-star boosts last under two months and become a liability ([arXiv 2412.13459](https://arxiv.org/abs/2412.13459)).

## A two-week pilot, a ten-week build, and a mid-January verdict

**Next two weeks (to ~Oct 27, 2026)** is about answering one question cheaply: *is there a measurable effect to build on?*

| # | Action | Done when |
|---|---|---|
| 1 | Owner submits the employer OSS/moonlighting clearance request | Request filed, with a written description framing MEND as developer-correctness tooling |
| 2 | Add the differential old-version gate to `mend verify`; time all 33 fixtures | Every fixture passes or is fixed; per-fixture verify time recorded |
| 3 | Check whether ruff (and pyupgrade) already flag each of the 33 patterns, `np.trapz` first | Overlap table committed. Patterns ruff already covers lose "differentiated" status. |
| 4 | Ship the Claude Code plugin: SessionStart lookup injection (fact-phrased, ≤10 lines) + PostToolUse `mend check` with exit 2 | Works end to end on a sample repo; no public launch yet |
| 5 | Prototype griffe diff on ~10 watchlist libraries' releases from the past 12 months | Candidate list of removed/changed symbols with the false-positive rate noted |
| 6 | Pilot bench: convert ~15 fixtures plus ~15 new post-cutoff candidates into Harbor tasks with implicit versions; run A0, A1, A4 on one model, k=3 | A measured A0 failure rate and a first paired A4-vs-A1 signal |

**Months one to three (to ~mid-January 2027)** builds the real thing if the pilot shows any A0 failures that A1 does not fix. Weeks 3–6 automate the pipeline: release events, griffe plus release-note extraction, LLM drafting, the four verification gates and the probe step, all on scheduled Actions. The target is about 100 post-cutoff candidates and 50+ verified, probed fixtures, with review time per fixture under 15 minutes. Over the same weeks, add the pre-commit hook, the GitHub Action, `mend context`, a semgrep rule-pack export, the `SECURITY.md` trust controls and catalog signing. Weeks 6–10 run MEND-Bench v2 at full size: ≥100 tasks, all arms including Context7 and the oracle, two models plus Claude Code and Codex on a subset, and a private held-out split. Weeks 10–12 publish the results, *including negative ones*, as a blog post, HF dataset and arXiv draft. That publication is the launch moment: plugin marketplace submission, registry listings and a multi-channel post.

**Kill/continue criteria, assessed around mid-January 2027:**

| Signal | Continue as tool | Pivot to benchmark-first | Stop |
|---|---|---|---|
| Baseline-failing tasks found by the probe | ≥50 | 20–50 | <20 (models already know nearly everything) |
| A4 vs best of A1/A2, paired | ≥10-point reduction in repeat failures, 95% CI excludes zero | Not significant, but A0 failures are real and refresh monthly | — |
| False-positive harm (reverse-anachronism tasks) | ≤2% of tasks broken by MEND | — | MEND regularly breaks correct code |
| Pipeline yield | ≥10 verified post-cutoff fixtures/week at <15 min review each | Pipeline works but review cost is high | Can't sustain without hand-authoring |
| Adoption after launch (rough, given HN's ~289/week average) | ≥500 stars or visible plugin/Action users within 6 weeks | Benchmark cited or run by others | Neither |

The "pivot to benchmark-first" column matters. If MEND-the-tool does not beat a one-line versions hint plus Context7, the post-cutoff probe data and refreshing benchmark are still novel, citable assets. That path serves the reputation goal arguably better than another MCP server.

**Owner-only decisions and actions.** Only the owner can do the following. Obtain **written employer pre-clearance** before any public promotion, and keep strict separation of personal equipment, personal AI and API accounts, and off-hours work. Inventions that "relate to the employer's business" are the carve-out in California Labor Code §2870-style statutes, and an AI-coding-assistant correctness tool plausibly does ([Terms.Law](https://terms.law/2025/07/04/employees-side-projects-who-really-owns-what/)). Commit to **not framing MEND as security tooling**. Choose the **data licence** (CC-BY-4.0 for attribution and reputation, or CDLA-Permissive-2.0 for frictionless model-vendor use). Set a **personal API budget** for benchmark runs; the pilot should cost well under the full run. Decide on the **positioning line and name usage** ("witness programs," "regression tests for your coding agent"). Decide whether to **accept outside fixture contributions now or after the pipeline lands**; later is recommended, to protect review time. Decide whether to **pursue an arXiv/workshop paper**. Set a **weekly time budget** and treat a missed pilot deadline as information about sustainability.

## Conclusion

The research changes what MEND's first benchmark result means. "Frontier models rarely repeat these failures" is not a verdict against MEND. It tells MEND where to aim: the problem migrates continuously to whatever changed since the last training cutoff, and every model release moves it again. A static, hand-built catalog will always describe yesterday's problem. A pipeline that detects new breaking changes, proves them, and *measures which models still fail them* describes tomorrow's, and that measurement is the one asset none of Context7, Tessl, codemods or the "Stack Overflow for agents" projects produce.

The second shift concerns delivery. The ecosystem has spent two years building retrieval surfaces that agents mostly do not call. The interventions with real evidence behind them are deterministic: always-present context and checkers that fire on every write. MEND's executable fixtures already fit that model, and after ContextCrush its data-not-instructions design is a selling point. The honest risk is that a one-line "here are your pinned versions" hint captures most of the benefit. The plan above is built to find that out within three months, and either answer leaves the owner with a credible open-source asset.
